# Google Earth 與 Google Maps 街景建模

用於實際建築重建，以及使用者指出寬度、屋頂、中庭、入口或地下車道不符時的修正。Earth 提供平面與體量關係，街景提供地面立面；兩者與使用者照片交叉核對後，建立可編輯的原創幾何。

## 1. 確認位置與參考狀態

先開啟使用者提供的 Earth／Maps 連結，依路口、道路名稱、入口與周邊建築確認標的。搜尋圖釘或商家名稱不代表基地邊界。使用環境提供的瀏覽器或電腦操作工具；只能讀到文字而看不到影像時，不能宣稱已查看 3D／街景。

記錄地址或經緯度、參考連結及查閱日期。拍攝日期以畫面實際提供的日期為準；未提供便寫「未知」。街景版權年份不是拍攝日期，移動到另一個全景後也要重新確認日期。若工具提供 pano ID 可補記，但仍保留位置，因 pano ID 可能改變。

使用者指定的參考狀態優先。不同年代的屋頂加蓋、圍牆或入口有差異時，記錄採用哪個版本；無指定時以可確認的最近狀態為主，其他影像補足沒有變動的部位。不要把不同年份的增改建無說明地拼成同一現況。

先列出主地標、具名周邊建築及可簡化的背景街廓。具名建築也屬於重建標的，不能套用隨機盒體後只驗收主塔。逐棟建立觀察表，後續跟著修正更新；未看清的部位保留「未知」：

| 棟體／部位 | 參考視角／位置 | 拍攝日期與連結 | 實際可見與模型採用構造 | 推估／遮蔽／待確認 |
|---|---|---|---|---|
| 主棟屋頂 | Earth 俯視 | 畫面日期或未知；原連結 | 外輪廓、屋頂凹口、棟間空地 | 屋頂是否覆蓋中央空間，待斜視確認 |
| 同棟南側／側翼 | Earth 不同方向斜視 | 畫面日期或未知；方向／連結 | 覆蓋屋頂、退台、露臺與高低關係 | 樓高、被鄰棟遮住的牆面 |
| 具名鄰棟入口 | Maps 街景／使用者照片 | 畫面日期或未知；位置／檔名 | 門窗、入口、圍牆、坡道起點 | 地下深度與無法看到的內部 |

## 2. Earth：先建立平面，再核對體量

1. 切至俯視，確認北向與街道方向。畫出主要棟體、附屬體、空地、圍牆和入口的相對位置，記錄地理方向如何對應 Blender 軸向。
2. 沿實際可見邊界記錄寬度、深度、間距、退縮與凹口。連續棟體可能跨多戶；不要以屋頂數量推定戶數，也不要把 L／U 形輪廓拆成互不相連的窄塔。
3. 區分屋頂投影、主體外牆、露臺、中庭及採光罩。懸挑屋頂的邊緣不一定是地面牆線。記錄屋頂的連續面、缺口、棚架和開放區域。
4. 旋轉到能看到遮蔽部位的斜視角，核對側面深度、前後錯位、樓層退縮和屋頂高低。以能確認形體的角度為準，不為湊固定張數重複擷取相同資訊。

每棟的證據需涵蓋外輪廓、屋頂構造、退台／層數及主要入口。從相反方向或另一側查看，直到重要部位能判讀；主塔、鄰棟或植栽遮住目標時，調整中心、距離及俯仰再看。記錄實際看清的面，不能把仍被遮住的視角記為已核對。屋頂與立面資訊足夠時即可停止，不要求無意義的固定角度配額。

深色中央區域不等於露天中庭：用斜視確認其標高、曲面、屋面接縫及與周圍屋頂的連接，再以街景、館方照片或平面圖交叉判讀。例：世貿一館的中央覆蓋屋頂不能改成草坪；同樣，真正的露天凹口也不能用屋頂補平。這種「覆蓋／開放」關係及退台輪廓是必要構造，不能用「尺寸近似」略過。資訊不足時註明待確認，避免把猜測寫成觀察。

使用目前工具支援的拖曳、滾輪縮放與畫面控制；環境支援中鍵旋轉時可使用。先確認實際工具 API／操作說明，不編造滑鼠參數或假裝旋轉成功。每次操作後查看結果，再決定下一個角度。

需要尺寸時，使用 Earth 的量測工具，在俯視狀態選取可辨識的端點並記錄單位。量測可能受 3D 地形與建築影響，也不計入高程變化；不要把平面距離當成樓高或車道落差。無量測工具時，以已知尺寸或相對比例估算並標明依據。

在專案來源說明中分開記錄「畫面量測值」「模型採用值」「估算方法／限制」。模型尺寸按證據精度取合理位數，不用長小數暗示測繪精度。樓高、地下落差及不可見的後牆要另行推估。

Earth 的攝影測量網格可能有變形、糊窗或植栽黏在牆面的現象。用它判讀體量，細部開口以街景與清楚照片核對。此流程不需要下載 Google 3D tiles、抽取原始網格或取得 API 金鑰。

## 3. Maps 街景：沿道路核對立面與入口

從 Maps 的街景入口或 Pegman 查看可用街景；有「更多日期」時，可用來辨識增改建。沿道路移動到正面、轉角、側面及車道入口，記錄每處實際能看見的構造：

- 窗與陽台的排列、拱窗、牆帶、簷口、外牆顏色，以及轉角後的延續。
- 圍牆、庭院門、車庫門、雨棚、道路與基地地坪的銜接。
- 地下車道的起點、下降方向、可見轉折、擋土牆、門與淨空。

廣角街景有透視變形，畫面中的像素寬度不能直接當成公尺。以 Earth 平面關係校正寬深，以街景校正立面構造。移動或縮放後確認仍在同一標的；被遮住的構造列為未知，不憑空增加地下格局。

沒有街景覆蓋、Earth 沒有 3D 或工具無法顯示時，改用使用者照片與可查看的其他來源，繼續完成可確認部分並說明缺少的角度。只有關鍵輪廓仍互相矛盾時，才提出具體問題。

## 4. 粗模核對後再做細節

先建立主要體量、凹口、屋頂、圍牆及基地地坪，以俯視和對應斜視 render 比對。寬深、棟距和屋頂退縮合理後，再添加窗、欄杆、材質、植栽和家具。不同棟體應保留可辨識名稱，供來源與幾何檢查使用。

用日間或白模分別查看各具名建築，對照來源的方向，核對中央空間是否有屋頂、退台層次、主要入口及附屬連接。先解決足以改變建築辨識的矛盾，再增加立面細節或夜景效果；夜色、標籤及主塔構圖不能代替這一步。

地下車道需使用真正下降的網格，與入口、擋土牆及門的位置相符。坡道上方的基地地坪、道路及檢視器額外建立的地板都必須留出開口，不能用完整平面把坡道覆住。只有入口可見時，建模到可確認的範圍，並標示地下深度／後續走向為推估。

需要查看車庫門後方時，可提供門的獨立顯示控制，維持正常關門外觀與坡道檢視兩種狀態。分開門、坡道與地坪的圖層，不能把隱藏地坪當成完成開口。

收到使用者標色或圈選的修正時，把範圍對應到模型棟體，更新觀察表與粗模。實際修改寬度、深度、屋頂連接或凹口；視角調整只用於比對，不能代替幾何修正。

## 5. 從匯出結果確認修正

- 依標的提供俯視、重要斜視與入口視角；有坡道、露臺或凹口時，增加能確認它們的視角。與來源使用相近方向與投影，避免只展示最不容易看出錯誤的角度。
- 檢查實際網格與 GLB 的棟體寬深、間距、屋頂連續性、凹口／中庭開放範圍。必要時從頂點與 bounds 計算幾何尺寸；漂亮的 render 不能證明尺寸正確。
- 分開記錄檔案驗證與外觀驗收。GLB 可讀、主塔高度正確或 HTML 內嵌一致，只證明相應項目；不能據此宣稱鄰棟外觀正確。逐棟對照觀察表，列出已確認構造、仍未知部位及比對圖。
- 有地下車道時，確認坡道起終點高度、下降方向及上方淨空，並在 Blender 與 HTML 檢視器都查看地坪是否遮擋。
- 每次改幾何後重新匯出 GLB、打包 HTML，確認 HTML 內嵌模型與最新 GLB 位元組相同。重新開啟交付的 `.blend`，檢查外部資產路徑與相機。
- 為本次重要修正加入適當幾何檢查；檢查應能抓到真實比例或遮擋錯誤，不用單純重述建模參數的斷言代替驗證。
- 使用者指出某棟不符時，記錄原先漏看的角度或誤判，重新取證、修改幾何並展示同方向修正版。例如覆蓋屋頂被誤建成中庭，可對實際匯出三角形取樣確認中心上方有屋面；仍須視覺核對曲面與退台。

交付來源／日期／方向說明、尺寸推估、仍未確認的部位、可重建腳本及本次驗證結果。保留舊版，修正版用獨立輸出名稱。完整交付檢查見 [建模與驗證](workflow.md)。

## 官方操作與限制來源

- [Google Earth：量測距離與面積](https://support.google.com/earth/answer/9010337?co=GENIE.Platform%3DDesktop&hl=en)：俯視量測、精度與高程限制。
- [Google Maps：使用街景](https://support.google.com/maps/answer/3093484?co=GENIE.Platform%3DDesktop&hl=en)：開啟街景、移動／縮放與歷史日期的可用性。
- [Street View metadata](https://developers.google.com/maps/documentation/streetview/metadata)：拍攝日期可能只有年／月或缺少，pano ID 可能改變。此文件用於理解來源紀錄，不要求呼叫 API。
