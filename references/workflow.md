# 建模與驗證

## Blender

檢查目前場景和檔案，另建命名場景；不要刪除使用者物件。以獨立輸出目錄避免同名 `.blend` 覆寫。背景模式下若沒有 `bpy.context.window`，不要依賴視窗切場景；使用適合目前 Blender 版本的 context override，或在專用背景程序建立場景。

大量 primitive operator 會觸發 dependency graph 更新，生成上千物件可能耗時數分鐘。先合併合理數量的網格；遇到效能瓶頸時才改用資料 API、共用網格或實例。不能因為 MCP timeout 就重複排程同一建模工作。

長任務建議寫入專案內 job-status.json：開始為 running，成功包含輸出路徑與統計，失敗包含 traceback。poll 該檔案，不持續向忙碌的 Blender 主執行緒塞入請求。若進度不明，先查程序與輸出，不能把排程成功當作完成。

需輸出可攜 glTF 的材質：使用 Principled BSDF 的基本 PBR 輸入。程序紋理如未 bake 可能無法等價匯出。不要宣稱 Blender render 與瀏覽器完全一致。平面迴廊、葉片與湖面應有正確法線；雙面材質是展示選項，不是拓樸修復。

避免廣場 disk、環形路面和步道交疊在完全相同高度。檢查完整鳥瞰及接近入口的視角，確認陰影、浮空物、露出的原始 Cube、湖岸與步道銜接。

匯出前選取本場景模型，使用 `use_selection=True, use_active_scene=True`。解析 GLB 確認預設場景、集合及模型尺度，不只看檔案是否存在。原始使用者場景可保留在 `.blend`，但不應混入 GLB。

## HTML

輸出前檢查：

- GLB header／長度有效、accessor bounds 有限、只有目標場景。
- 內嵌 base64 解碼與 GLB 位元組相同，沒有未替換的模板標記。
- 單檔離線版本沒有外部 script／stylesheet／模型請求；來源連結可保留供使用者點開。
- 頁面解析失敗有清楚錯誤狀態，不能永久停在載入中。
- 視角切換後不把使用者手動拖曳拉回；自動環繞可停；手機面板不完全遮住模型。

若執行瀏覽器驗證，檢查載入、四個視角、光照、白模、圖層切換、reset、下載與窄螢幕。記錄實際測試結果；靜態檢查不能代表這些互動已測試。

如工具被額度或審核阻擋，記錄被阻擋步驟並交付已完成部分；不得換途徑繞過拒絕。不要寫入憑證、Sites project ID、暫存授權或使用者绝對路徑到 skill 範例。
